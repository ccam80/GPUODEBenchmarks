# Numerical references and finals

## Golden references

Machine-independent Float64 references, one per problem, solved with the
problem's `golden_algorithm` at its `golden_tol` from
`runner_scripts/problems.csv`:

- `golden_<problem>_131072.csv` — the final states of the 131072-trajectory
  work-precision (wp) ensemble, one row per trajectory, no header. Generated by
  `runner_scripts/golden/generate_golden.jl`; an existing file is kept unless
  `--force`.
- The numerical-equivalence (ne) ensemble is the first 1024 trajectories of the
  wp ensemble, scored on the first 1024 rows of the same file.
- `golden_ne_<problem>_1024.csv` — `<sweep>,<states...>` grid and reference of
  the problems listed under `ne_legacy_grid` in `runner_scripts/protocol.toml`,
  from `runner_scripts/numerical_equivalence/generate_golden_ne.jl`.
- `golden*_retcodes.csv` — unconverged golden rows as `row,retcode` (1-based);
  absent when every solve converged.

## Per-machine finals

`<os>_<gpu>/<problem>/<file>.csv` holds the final states of one package's
32768-trajectory timing point (row per trajectory, no header), written by the
performance sweep whenever it times N = 32768: `cubie_unadaptive.csv` and
`cubie_adaptive.csv` (`cubie_mlir_*` for the MLIR backend), `jax.csv`,
`pytorch.csv`, `julia_fixed.csv` and `julia_adaptive.csv`, `mpgos.csv`, and
`myokit_cuda.csv`. `compare_numerical_results.py` compares every pair of those
files with `numpy.allclose` (`rtol=1e-4`, `atol=1e-6`), grouped by machine, and
exits 3 when fewer than two files exist.
